ivenna receive CHANNEL_ID [--timeout MS]
ivenna receive CHANNEL_ID --follow

Pass the complete ID returned by open_channel. Set DATA_DIR to the instance
data directory so both processes resolve it to the same absolute path. Run
receive with the same ivenna build, effective user ID, and Linux network
namespace as the kernel. Host commands inherit DATA_DIR and can call "$IVENNA".

Start receiving before sending. Without options, wait for one message.
Use --timeout MS to limit that wait to 1 through {d} milliseconds.

A completed single read writes one JSON line to stdout and exits with status 0.
The status field gives the outcome.

  message    One message was read. The text field contains the message.
  timeout    The wait elapsed before a message arrived.
  closed     The channel closed before the read matched a message or timed out.

Use --follow to stream message records, one JSON line per message. The command
flushes each line before requesting the next read. It finishes writing any
matched message and exits with status 0 when it observes the channel close.
If the output pipe closes during a wait or write, either mode exits with
status 0, possibly without a complete line for the current read.

An unknown ID on the initial request or an unavailable channel service
produces a diagnostic on stderr and exit status 1.
