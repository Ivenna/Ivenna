Cursor changes and write receipts

Set "to" to the new source position as a string. Use the saved cursor from
inspect as "from". When no cursor has been saved, omit "from" or send null.
Use "from": "" for a saved empty string. A cursor change succeeds only when
"from" matches the saved position.

The JSON reader accepts up to 4 MiB of decoded text per string. See the publish
fields for the report text limit.

Read the JSON string on stdout and check the exit status.

Exit 0
  "accepted"         The write committed.
  "duplicate"        publish recognized a key already accepted on this
                     subscription. The retry leaves the queue and cursor
                     unchanged, even after the focus has received the report.

Exit 1
  "withdrawn"        The ID is unknown or withdrawn. Stop using this ID.
  "cursor_conflict"  "from" differs from the saved cursor. Read it with inspect
                     and check which items remain. A publish rejected for this
                     reason leaves its key available for retry.
  "busy"             The store is busy. Retry later.
  "storage_full"     Free storage before retrying.
  "invalid_request"  Correct the arguments or the JSON request.

If the receipt is missing or incomplete, the write may already have committed.
Check stderr for diagnostics. Retry a publish request on the same subscription
with its original key. For checkpoint, inspect the saved cursor before deciding
whether to retry.
