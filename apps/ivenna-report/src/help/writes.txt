Cursor changes and write receipts

Set "to" to the new source position as a string. For "from", use the cursor
value returned by inspect. If the cursor is null, you can omit "from".
If it is the empty string, pass "from": "". The reporter's JSON reader
accepts up to 4 MiB per string.

Read the JSON string on stdout and check the exit status.

Exit 0
  "accepted"         The write committed.
  "duplicate"        Returned by publish when this subscription already
                     accepted the key. The retry queues no report and keeps
                     the saved cursor in place.

Nonzero exit
  "withdrawn"        The ID is unknown or withdrawn. Stop using this ID.
  "cursor_conflict"  "from" differs from the saved cursor. Read it with inspect
                     and check which items remain. A publish rejected for this
                     reason leaves its key available for retry.
  "busy"             The store is busy. Retry later.
  "storage_full"     Free storage before retrying.
  "invalid_request"  Correct the arguments or the JSON request.

Check stderr for diagnostics if the receipt is missing or incomplete. A write
may have committed before the reporter could print its receipt.
