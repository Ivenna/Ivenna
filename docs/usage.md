# 使用会话

以下示例使用服务地址 `http://127.0.0.1:5882`；连接其他服务时替换地址。启动本地服务的步骤见[运行指南](running.md)。

Ivenna 持续维护会话及其历史。创建会话后，后续输入通常沿用同一个会话 ID。

## 创建并继续会话

创建会话时，提交一个 JSON 对象，其中的字段作为每次输入的默认值；没有默认字段时可提交 `{}`：

```sh
curl http://127.0.0.1:5882/sessions \
  -H 'Content-Type: application/json' \
  -d '{"language":"zh-CN","timezone":"Asia/Shanghai"}'
```

成功时返回 `201` 和会话记录，初始状态为 `waiting`。创建本身不会开始模型处理。`language` 和 `timezone` 是自选字段示例，服务将它们提供给模型，没有针对这两个字段的专门处理。

记下响应中的 `id`。假设它是 `1`，提交第一条输入：

```sh
curl http://127.0.0.1:5882/sessions/1/inputs \
  -H 'Content-Type: application/json' \
  -d '{"message":"请记住，我正在学习法语。"}'
```

响应 `202` 及 `{"id":1,"status":"accepted"}` 确认输入已接收并交由后台处理。会话的执行状态通过后续查询取得。模型运行由服务管理，HTTP 请求结束后仍会继续。

查询同一个 ID，查看处理状态和已保存的历史；处理尚未结束时可稍后再次查询：

```sh
curl http://127.0.0.1:5882/sessions/1
```

后续仍向 `/sessions/1/inputs` 提交输入。运行期间提交的输入会先排队，在当前轮次结束后接入。会话进入 `waiting` 后，提交新输入会沿着已有历史继续。

若希望不添加输入而继续执行，可调用：

```sh
curl -X POST http://127.0.0.1:5882/sessions/1/resume
```

`failed` 会话也可通过提交新输入或调用此接口继续。

## 输入字段

创建会话和提交输入的请求体都必须是 JSON 对象。服务按顶层字段合并会话默认值和本次输入：本次输入中的同名字段覆盖默认值，只对本次输入生效。嵌套对象和数组保持原结构，同名嵌套对象会整体覆盖。

例如，会话默认值中的 `language` 为 `zh-CN`，某次输入提交 `{"language":"en","message":"Summarize what we know."}`，这次提供给模型的语言字段为 `en`，下次未指定时仍为 `zh-CN`。

`session_id` 始终由服务设为当前会话 ID；合并后仍没有 `message` 字段时，补为空字符串。其他字段可按使用场景自行组织。

## 接口与状态

接口返回 JSON。`:id` 为创建会话后取得的 ID。

| 接口 | 请求体 | 成功响应 |
| --- | --- | --- |
| `POST /sessions` | 默认字段对象 | `201`，完整会话记录 |
| `POST /sessions/:id/inputs` | 本次输入对象 | `202`，`id` 和 `status: "accepted"` |
| `GET /sessions/:id` | 无 | `200`，完整会话记录 |
| `POST /sessions/:id/resume` | 无 | `202`，`id` 和 `status: "accepted"` |

会话记录包含以下字段：

| 字段 | 含义 |
| --- | --- |
| `id` | 后续请求使用的会话 ID |
| `user_fields` | 创建会话时保存的默认字段 |
| `status` | 当前会话状态，见下表 |
| `messages` | 已保存的会话历史 |
| `pending_inputs` | 已接收、尚未接入历史的输入 |
| `error_message` | 本轮失败的错误名称，无错误时为 `null` |

| 状态 | 含义 |
| --- | --- |
| `waiting` | 当前处理已暂停，可提交新输入或调用恢复接口继续 |
| `pending` | 已排队，等待后台执行 |
| `running` | 正在处理模型请求或工具操作 |
| `failed` | 本轮失败，可查看 `error_message` 后继续 |

请求体格式无效时返回 `400`。查询或提交输入的会话不存在时返回 `404`。恢复接口只接受 `waiting`、`failed` 或 `pending` 会话；会话不存在或正在运行时返回 `409`。错误响应使用 `{"error":"错误代码"}` 格式。

## 持续使用时的行为

服务重启后，原先处于 `pending` 或 `running` 的会话会从已保存的历史继续。中断前已经执行、尚未记入历史的操作可能再次执行。

默认字段和历史按会话保存，Ivenna 自主管理的记忆库则由所有会话共享。Ivenna 可以创建、修改和删除其中的表与数据。

当前会话保留完整历史，尚未实现自动压缩。长会话仍受所用模型的上下文窗口限制。
